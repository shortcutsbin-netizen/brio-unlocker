# Session dashboard and lifecycle contract — design stage

A session is ONE successful script installation/run. Reinjection ends the old session, destroys old owned resources, starts fresh totals; reconnecting or playing another match within the same instance preserves the same totals. No cross-run persistence by default. No site/native assets purged. Saved custom uploads/preferences survive reinjection.

Use O(1) scalar accumulators: completed matches, wins, eliminations, damage, builds, native match duration, placement count/sum/best, HP/shield loss, sampled travel/projectile totals with independent coverage counters, bounded fixed known-weapon holding seconds. Update once from accepted terminal result after visible native end state. Deduplicate only the current match epoch/terminal token; do NOT retain an unbounded Set of every match ID. Duplicate/late terminal events must not double-count or mutate a destroyed instance. Abandoned/disconnected matches without native terminal remain uncounted; do not invent placement or label missing observation as zero.

Derived: win% = wins/known native placement outcomes (completed when all outcomes known); kills/game = eliminations/valid elimination-results count (completed when all known); average placement = placementSum/validPlacementCount; damage/game, builds/game, average survival = corresponding totals/valid denominators, rates/min require valid native duration. Sum observed samples only, label as observed and disclose coverage. Weapon shares use sum of sampled holding time, never all match duration. Prefer no recent-match history or trend array: panel can display totals, rates, observation coverage and a fixed weapon distribution without storing raw matches, names, event packets, player objects or logs. Unknown weapon keys ignored/Other bucket in fixed schema; no arbitrary-key growth. All visual samples are fixtures, not an additional data probe.

Use a compact native home side-ad slot (300x250 reference, verify host slot at integration) with fixed-area body scrolling. Header remains visible; all sections reachable by mouse, keyboard, touch. Accessible scrollable region with label, normal focus support; no autoplay scrolling. Provide completed/empty/partial coverage states in sample. Reuse debrief theme/components, do not expand/rewrite native home controls. Finalized socials separate ad slot remains unchanged.

Reinjection lifecycle: new installer first calls old owned instance.destroy(); generation/epoch invalidation precedes all asynchronous cancellation; stale asset promises may resolve but must discard/release their results. Own/list and cancel rAF, timers, observers, abortable listeners; restore only descriptors/wrappers still pointing to OUR wrapper (do not overwrite another extension); detach all owned DOM/canvas/styles and scene nodes; restore native resource refs; revoke only OUR object URLs; clear runtime maps/image decode references/promises/frames/session counters/retained logs and set closed/destroyed. Release/dispose ONLY exclusively owned textures/canvases, never shared native resources. Persistent custom artwork in IndexedDB is NOT a leaked runtime duplicate; preserve it while dropping per-run decoded caches. Share identical pickaxe inventory/held texture, lazy decode selected assets and use a bounded cache/LRU, not all16sets GPU-resident. Reuse CSS atlas sheet for menu thumbs; unload/clear preview canvas resources on menu closure or instance destroy.

Memory acceptance at IMPLEMENTATION: repeated inject/open/close/match/end paths show singleton root/style/session object, original descriptors restored, no growing owned timer/listener/objectURL counts, bounded cache bytes/entries and no stale completion retaining prior player graphs. Profile retained heap/drawable/cache resources across repeated cycles, including GC when available. No claim of zero possible duplication or guaranteed browser memory reclamation: GC/GPU/native allocations are not under complete script control. Numeric session aggregates remain bounded in space independently of match count. Production terminal removal and existing diagnostics must not add unbounded logs/session history. Test mock lifecycle invariants locally first, then final bounded gameplay suite (max2matches), not ten test games.
