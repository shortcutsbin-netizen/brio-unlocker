# V1.71 acceptance check — maximum two played matches

Hell (including trails), the session-panel design and in-match cosmetics are accepted. No repeated Hell sweep, forced win, gun hunt, new asset capture, terminal or log upload. This candidate has no in-match Extras button; configure from home. The victors feature is deferred.

1. **Start fresh and record the memory baseline.** Reload https://buildroyale.io and let home finish loading. Before running BRIO, open Chrome's Task Manager with Shift+Esc and note this game tab's Memory footprint. If available, enable the JavaScript memory column by right-clicking the column headings and note it too. Close Task Manager without ending the process. Keep the same tab/window size for the later readings; no forced garbage collection or memory upload is required.

2. **Install v1.71 once.** You can use the complete `dist/brio-v71.min.js` with your established console/snippet method. To check one-click installation instead, create/edit a bookmark, name it BRIO UNLOCKED, and paste the entire contents of `dist/brio-v71.bookmarklet.txt` into its URL field. Its prefix is `javascript:` with **one colon**. Save it, stay on the game home page and click it once. Use one installation method, not both. Confirm the Locker/Extras headers and socials show **v1.71**, with no terminal or floating in-match control. The socials GitHub button should open `shortcutsbin-netizen/brio_unlocked`; Discord remains the non-clickable ads0210 badge. If the version is wrong or installation fails, stop before playing and report it.

3. **Check new home/menu changes without a match.** The bottom-right ad slot should contain Changelog. Confirm the v1.71 header, bullet wrapping and scrolling all the way to the last bullet; native ad content must not remain underneath it. The accepted session panel should retain its layout and clearance from Join Party. In Unlocker, glance at one original set's head/body/pickaxe/glider cards: each should have a red Mythic glow. Native cards should follow their rarity; an existing imported item, if you have one, should be gray/Common. Do not import new art or inspect all 16 sets just for this test. Check the selected pickaxe in the running preview and a glider once: the pickaxe should look proportionate and sit behind the body/head correctly; the larger glider should be fully visible. In Extras → Modifiers → Indicators, enable Loot indicator temporarily, expand Loot choices, and scroll its grid: each weapon should occupy an evenly arranged card with only its own eligible Gold/Red buttons. Red-only weapons should have one Red choice. You do not need to find those guns in a match. Close/reopen Locker once to check the preview/cards rebuild normally.

4. **Play match 1 with a reduced General Advantages configuration.** Turn Hell and other challenges off. Click Use preset under General Advantages. Confirm All gliders invisible is now off and absent from the preset description. Turn **Low-health visual warning off** to remove one included modifier, then enable **Nearest chest indicator** as an extra. Leave inventory size Large and warning thresholds at defaults. Play normally; no actions or encounters are required beyond ordinary play. Give the already accepted cosmetics/aids an exception-only glance. No floating Extras button should appear. At the end, the Modifiers panel must **not** show General Advantages or General Advantages (edited). It should list the individual modifiers used, including Nearest chest indicator; Low-health visual warning should be absent because it was disabled before this match. Challenges should show None. Check that native end-screen/Play controls still work. Return home, wait about 10 seconds for cleanup/settling, and note the same tab's memory reading and one completed session result.

5. **Play match 2 with intact General Advantages plus an extra.** From home, click Use preset again, then enable **Nearest chest indicator** again. Do not remove a preset member, change inventory size or change warning thresholds for this match. Play normally. At the end, Modifiers should show **General Advantages** plus **Nearest chest indicator**, without expanding all preset members and without an Edited label. All gliders invisible must remain off unless you deliberately enabled it separately. Challenges should still show None. Return home, wait about 10 seconds, record the same tab's memory reading again, and check two completed results with sensible totals. Mark any unencountered visual condition unobserved; do not play a third match to find it.

6. **Check replacement once after the final memory reading.** Run v1.71 again on home, preferably by clicking the bookmark if you chose that method. There should be one socials strip, one session panel, one changelog and one pair of home menus. Ads should remain suppressed. Session totals should reset to zero for the new run; cosmetic selections, Extras preferences and saved imports should survive. Open Locker/Extras once to confirm normal operation. The same bookmark must run directly without a console step.

7. **Report focused findings.** Include browser/window size, pickaxe/glider preview proportions, rarity glows, weapon-card spacing, changelog placement/scrolling, GitHub destination, absence of in-match controls, the two modifier reports, session arithmetic and the three memory readings (before BRIO, after match 1, after match 2). Distinguish Memory footprint from JavaScript memory when available. Quote any menu-footer error. Screenshots of a specific defect are optional. Browser memory need not return to the exact fresh-load value, but report continued large growth, lag or a tab crash. No logs, extra matches, heap capture or additional test suite are required.
