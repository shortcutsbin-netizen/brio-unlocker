# V62 — short live procedure

Use `dist/brio-v62.min.js` (the complete standalone Console payload), copied raw once on the normal game home page. This returns to the established user-play → exported evidence → repository development pipeline. No cloud/local remote-control setup or new asset capture is needed.

1. Open Extras → **Test bots + contents**, then ordinary Play. The profile backs preferences up once, enables spread and the existing bot/three content options, and disables Hell. Existing other choices persist. **Restore saved settings** remains available.
2. Play one natural match. With any naturally obtained gun, briefly aim around the player and fire hip/ADS normally. Observe whether the cone starts near the barrel and follows actual bullet direction. No all-gun, fixed-aim, clip-count or rarity task.
3. Open naturally available containers/fishing normally. No every-kind quota, airdrop hunt, manual probe arming or repeated baseline match is required. Player/container/descriptor/tuple/feature/performance evidence records passively within existing caps.
4. At match end—or earlier if something clearly fails—click **COPY RESULTS**, and upload the entire export as `logs/runs/v62-log.txt`. Separately report cone alignment and any obvious modifier/challenge regression. Mention only what you actually encountered; unencountered surfaces are unobserved.
5. If the cone is still wrong, include one clear screenshot/short clip showing the gun, cursor, full player, cone and a few bullets, with gun and hip/ADS identified. No second match is required merely to obtain it.

Bot and exact contents labels are still unresolved and should not be expected to appear. If you independently know a player's human/bot status, report the basis separately; apparent aim, names, IDs, cosmetics and spawn timing are not ground truth. Existing proven features are exception-only; no broad challenge cycling or PERF action is requested. Keep at most three distinct extra manual action types in a match; repeats of ordinary actions are fine, export is separate.

The next analysis must inspect V62's new evidence and numeric projection records before proposing another suite. A screenshot is required for another cone correction if these changes still fail; repeating guessed offsets is not an acceptable substitute.
