# V63 full test procedure

Use `dist/brio-v63.min.js`, the complete standalone Console payload. Copy its raw contents and paste once on the normal Build Royale home page; confirm **BRIO v63**. No browser-control setup, new asset retrieval, native keybinding changes or spread-recording quotas are needed. Do not reload during a live match.

1. **Prepare the full ordinary test profile on home.** Open Extras → Modifiers. Click **Set up normal test**, then **Set up V63 test**. The first enables the already-built supported modifiers and turns challenges off; the second enables the new custom crosshair and keeps bot/container/spread capture focused. The existing saved-settings backup is preserved. Other presentation choices/cosmetics remain; **Restore saved settings** is available after export. Flashlight starts off through the normal profile and is checked separately below. Close Extras and minimize the terminal if it obstructs play, then ordinary Play.

2. **Check the cone early with any naturally obtained gun.** Walk/turn without firing or ADS, then ADS/fire normally, then return to walking. Its origin should stay at the same aimed-position reference throughout, relative to the player/aim, instead of swinging with the lowered walking hand. Direction and empirical width should continue following the selected gun/mode. Check the softer rounded outline, curved outer/back edge and faint shaded interior. No all-gun, fixed-aim, clip-count or rarity task. If it still looks wrong, identify the gun/state and include one clear screenshot or short clip with player, gun, cursor, cone and a few bullets; no second match is required just for that evidence.

3. **Check NEW · CHECK: Enhanced/custom crosshair.** In Extras → Modifiers, find its blue flag. It starts enabled by the V63 profile. Try a different Cross/Dot/Ring preset and one color/size change; close Extras and check that the reticle follows the native aiming point. Native red hit confirmation should remain when a hit naturally occurs. Briefly turn **No crosshair** on and off in Challenges: the custom reticle must disappear and return. Turn the custom-crosshair modifier off once to confirm the native white reticle returns, then enable it again if desired. Its Reset restores only Cross/white/24px. If convenient, try an existing PNG or WebP upload (up to256KiB, maximum512×512pixels): it should keep aspect ratio; invalid/missing/pending images should leave the native reticle available. Upload is optional; report it as untested if skipped.

4. **Check NEW · CHECK: Flashlight mode.** In Extras → Challenges, find its blue flag and enable it. Start with Player follow, close Extras, and walk: the soft clear area should follow the player while the rest of the game canvas darkens. Change to Cursor follow, close Extras and move the cursor over the game: the clear area should follow it. Change radius once (80–600px); check that only the light size changes. Reset restores Player/220px without altering crosshair settings. Turn flashlight off and confirm the view clears immediately. It must not block clicks or obscure the Extras/terminal controls. If safe and convenient, optionally try a Hell on/off pair: the custom crosshair is suppressed, flashlight remains independently as selected, and saved modifiers restore when Hell is off. Leave Hell and flashlight off for the remaining ordinary checks.

5. **Continue one natural match with the built modifiers.** Observe naturally encountered health outlines, remote inventories, safe-zone edge/center arrows and distance, selected gold/red loot arrows, owned-ammo highlighting, and past bullet/throwable trails. Open available chests/crates/fishing/airdrops normally; no every-kind hunt or repeated opening quota. Bot/container/tuple/descriptor/native visual/performance evidence records automatically. Existing proven features need only exception reports; do not repeat meteor/cosmetic/foliage/warning-decision tests or exhaustively cycle every old challenge. Unencountered conditions remain unobserved. Keep at most three distinct extra manual action types per match; repeated settings edits are one type, and export is separate.

6. **Observe the natural match end if reached.** Flashlight must not remain over the end screen. Check the Match breakdown if shown and report missing/duplicated panels or obvious totals/layout issues. No forced win, second match or dedicated PERF action is required. Next Play should clear temporary visuals and start fresh tracking while retaining preferences and the uploaded crosshair; another match is optional rather than a prerequisite for this pass.

7. **Export and report.** At match end—or earlier if a clear failure occurs—click **COPY RESULTS** and upload the entire export as **`logs/runs/v63-log-2.txt`**. Preserve the existing `v63-log.txt`: despite its filename, that is the uploaded V62 export. Separately report cone walking/ADS/firing position and appearance; custom crosshair preset/restore/hit-marker/No crosshair behavior (and upload if tried); flashlight follow/radius/off/end-screen behavior; and any other obvious modifier/challenge issue. Mark skipped/unencountered checks as untested. After export, use **Restore saved settings** if you want your pre-profile preferences back.

Bot labels and exact unopened-container contents are still unresolved and are not expected to appear. If you independently know a player's human/bot status, report the basis separately; apparent aim, names, IDs, cosmetics and timing do not establish it. No guessed contents/NONE or bot classifier was added. The next analysis will inspect V63's new evidence and your observations before another release; there is no request for another asset pass or unchanged broad recon baseline.
