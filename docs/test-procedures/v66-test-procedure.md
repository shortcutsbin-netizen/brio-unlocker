# V66 full test procedure — maximum two matches total

One normal modifier match is the main check. A second match is optional for the remaining challenge review. **Do not exceed two played matches or add matches to fill missed conditions.** Existing proven features need exception reports only. There is no spread, bot-identification, container-opening, gun, rarity or kill quota.

1. **Load the complete V66 script on home.** Open `dist/brio-v66.min.js`, copy the complete raw file and run it once in the browser Console using the established workflow. Confirm **BRIO v66**. In Extras → Modifiers, click **Set up V66 modifiers**. This applies the supported normal profile, enables the newly completed storm-edge/high-contrast cues and custom crosshair, turns gameplay challenges off, and keeps your original settings backup. Every row should say **PROVEN** or **BUILT · CHECK**. Spread, standalone storm-distance and bot/content-screening controls should be absent. The safe-zone arrow still includes distance.

2. **Match 1: review the remaining modifier surfaces during ordinary play.** The new high-contrast cue is a yellow halo around remote players, not yourself. The new storm-edge cue is a thin cyan highlight on the actual visible world-storm boundary, following its native movement/shrink; it is separate from the projected safe-zone arrows. Check these when naturally encountered; do not hunt for a player or travel outside safety just to see an edge. If convenient, turn each new cue off/on once and check restoration. Also note your custom crosshair color, remote inventory slots/materials, safe-zone edge/center arrows, selected gold/red loot arrows, owned-ammo outline and past projectile trails when they naturally appear. These are the remaining built modifier checks; no every-item sweep is required. An existing local PNG/WebP crosshair upload is optional if convenient; otherwise mark upload untested.

3. **Observe the natural end of Match 1.** If reached, inspect the Match breakdown for readable layout, obvious duplicate/missing panels and agreement with native placement/eliminations/damage totals. Unavailable accuracy or per-player damage attribution should stay explicitly unavailable. No forced win, second ending type or repeated Battle Pass cycle is needed. If a clear failure makes play impractical, stop early and export. A screenshot or short clip plus the option/mode is useful for a visual failure; no extra match is required for it.

4. **Optional Match 2: highest-tier challenge review.** Only if you want to cover the outstanding challenge surface, return home and click **Set up V66 challenges (Hell)**. This explicitly enables every gameplay challenge at its highest tier and disables modifiers; monochrome and flashlight stay off so this review is readable. Expect hidden remote bodies/held parts, loot and builds; hidden map/crosshair/own inventory/health HUD; hidden storm, chests, info/pickup messages, hit/damage/progress cues, projectiles and held weapons as applicable. Native movement, collision, sound and gameplay continue normally. Report anything that visibly leaks or anything outside those scopes that disappears unexpectedly. If this becomes impractical, turn Hell off or stop early. Composite coverage does not independently prove every lower tier or child branch hidden by an ancestor; those remain unobserved rather than being called passed. Do not add another match to test them.

5. **Export once after the review, or at an early failure.** Click **COPY RESULTS** and upload the entire output as **`logs/runs/v66-log.txt`**, preserving earlier logs. The script automatically records **V66 COMPLETION AUDIT** at native match end and export, listing all 50 retained options, enabled states, reached/suppressed contexts and pending visual approvals. No separate PERF, probe, manual MATCH START or auto-cycle action is required. In chat, report the two new cues; custom crosshair color/upload if checked; any other BUILT · CHECK surface you explicitly observed working; Match breakdown appearance if reached; and any challenge leaks. Mark skipped/unencountered conditions untested. Keep at most three distinct extra manual action types per match; repeated settings edits count as one and export is separate. Use **Restore saved settings** after export if you want your prior preferences back.

The script completes all retained planned implementation work and gathers review evidence; it cannot turn unobserved conditions into visual approval. Remaining gaps will be updated from this log and your report without repeating finalized flashlight/outlines or retired spread/bot/contents work.
