# V43 live test

1. Reload Build Royale home. Open `dist/brio-v43.min.js` on GitHub; **Copy raw file**, or **Raw → select all/copy**, and paste the complete plain JavaScript into DevTools Console. Wait for READY / BRIO v43. Use native `(un)Locker` and Extras.
2. Extras → Modifiers: enable every blue flag: **Inventory: 5 item slots; Inventory: build materials/counts; Inventory: ammo by type; Screen chests; Screen airdrops; Screen fishing spots; Player health bars; Nearest player indicator; Nearest chest indicator; Nearest airdrop indicator; Permanent meteor location; Health/shield numbers; Low-health visual warning; Low-material warning; Identify bots.** No challenge required. Inventory size can remain XL. Keep other saved settings, including roofs, as desired; report them. Avoid player/bar hiding while checking numbers.
3. Only three extra gameplay action types:
   - **MATCH START** once at transition.
   - **Briefly pause near a still-unopened container before opening it normally** (about two seconds; repeat on chest/crate/drop/fishing when practical). This gives a settled pre-interaction replica sample; no CONTENT BASE/AFTER buttons. Normal interactions are sufficient; do not search the whole map or create extra chores.
   - **Open full map after a spawned meteor marker's usual expiry.** No arm action. Note separately what is visible on minimap/full map.
4. Observe during normal play: your own wood/brick/metal displays should independently flash/glow red below 30 (30 should not warn); remote material displays should not flash. Low-health player outline should glow/flash at HP≤30. Check black numbers/white outline inside native bars. Compare remote item/material/ammo artwork, fonts and counts against your own native HUD at the selected size. Note any fallback or missing layout. Existing arrows/cosmetics are preserved; report any regression without adding a special emote task this run.
5. After match: **COPY RESULTS**, then upload complete output as `logs/v43-log.txt` or a numbered dated match file. Include visual observations: native HUD match/differences; own-only material warnings and observed counts; health outline/numbers; meteor before/after expiry on each map actually seen; performance. Mention which container types were exercised. Missing meteor/low health/container is unexercised, not failed. If you know a current remote player is human, name them in feedback; no old IDs/names are reused as ground truth.

Capture/startup/schema/widget entries are important; do not trim them. Copy export is not a gameplay action type. Mock passes do not establish live visual correctness.
