# V46 live test

Use normal Play only. No manual match-start/probe arm, contents button or special emote task. At most three extra gameplay action types per match: unopened-container pause; post-expiry full map; brief builds/deployables. Repetitions do not add action types. COPY RESULTS is export.

1. Reload Build Royale home once. Copy the entire `dist/brio-v46.min.js` using GitHub **Copy raw file** (or **Raw → select all/copy**), paste in DevTools Console, and wait for **BRIO v46 / READY**. Keep your desired cosmetic choices. Minimize/drag the terminal if it covers gameplay.
2. Extras → Modifiers: enable all **24 blue flags**. These cover the three Inventory rows; Screen chests/airdrops/fishing; health bars/numbers; nearest player/name/chest/airdrop; permanent meteor; low health/material/ammo; Identify bots; highlighted/clean loot; high-contrast players; transparent foliage; build material labels; deployable labels/radius. Keep transparent roofs enabled. Leave hiding challenges and monochrome off during the primary comparison. Inventory XL is fine. The script logs all selected flags at Play; no additional verification chore is required.
3. Press ordinary **Play**. During normal collection/firing/reloading/switching, check **every gun slot**, including unequipped guns: glow outlines that slot when its displayed ammo (loaded + reserve; grappler/signal flare loaded only) is **below 20**. It should update after reloading, ammo pickup, swaps and empty/filled replacements. Exactly 20 or more, consumables and empty slots must not glow. If safely encountered, report a 19/20 boundary; no forced ammunition depletion is required. Individual materials below 30 keep their correct borders; remote material/ammo numbers keep flashing below 30/20.
4. Compare remote inventory backgrounds/art orientation/scale/font/counts/opacity/ammo stack row to native HUD. Empty remote slots have a red corner-to-corner X. Check larger nearest-player names at several directions, long names if encountered, and the name option off/on. Check three colored arrows, upright distance text, equal bars/numbers, low-health outline, high-contrast players, loot rings without glow clutter, roof/foliage transparency and chosen cosmetics. Record any discrepancy and whether a condition was actually encountered.
5. Extra action type **1**: pause about two seconds near an unopened target before interacting normally. Try normal **and legendary** chests, ammo/grenade crates, fishing and an airdrop when available. Note each actual type and whether any useful pre-open content overlay appears. Unencountered types remain untested; opening/removal/nearby drops alone cannot prove pre-open contents.
6. Extra action type **2**: after the meteor marker's normal expiry, open the full map and check the retained location; also observe the minimap. Extra type **3**: briefly exercise wood/brick/metal builds and any available deployable (campfire, boost pad, shield or drill); check labels and the supported effect-radius circle. Do not spend the round hunting an unavailable object.
7. Finish the match, click **COPY RESULTS** as a backup, then press normal **Play again without reloading or reinjecting**. Immediately check both maps: the old meteor must be gone. Old arrows/inventories/container overlays must clear; saved choices must persist and apply again. Repeat any missed conditions and check that a fresh meteor persists only in this second match. This second Play is essential for the reported carryover regression.
8. Optional secondary comparison in a later same-session match: test existing monochrome and hiding choices individually, then disable them on the following Play to confirm restoration. These can conflict with the visible primary controls, so state the settings/match used. Keep the same three-action limit; do not add special emote or manual probe chores. Native/Random/Invisible/Custom cosmetic alternatives can likewise be checked in later runs if you want live coverage of those modes.
9. After the final match click **COPY RESULTS** and upload the **complete** output as `logs/v46-log.txt`. The latest copy contains both runs from this injection. If the session ended early, provide the earlier backup too. Include observations for name readability, each-slot glow/replacements/counts, old/new meteors, other visible features, actual container/deployable types and performance. Keep all source chunks, incoming/environment records, HUD bindings, MATCH STATE RESET and V46 PROBE COVERAGE. Missing hooks, caps, errors and truncation are evidence gaps, not passes or impossibility.
