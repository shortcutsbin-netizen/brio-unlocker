# V1.71 memory findings

The user observed roughly 300 MB on a fresh page and 800 MB after two matches. Those are process observations, not an attribution of all 500 MB to one JavaScript object. This pass removes specific avoidable allocations and retained scene graphs without clearing shared game resources, stored preferences or imported art.

## Findings and changes

1. **Full-resolution blank roof copies.** V1.70 made a blank canvas at each native roof texture's resolution, encoded it to PNG, decoded another image, and cached the promise under a long-lived native image. The 20 available captured roofs total 21,887,500 pixels: **87,550,000 RGBA bytes / 83.49 MiB per extra copy**. Multiple browser/graphics copies are possible; that number is pixel arithmetic, not a measured process saving. V1.71 shares one ready **2×2 transparent canvas**. Each native sprite retains its original dimensions, placement and resource wrapper; the original image is restored before releasing ownership. Invisible cosmetic PNGs also use a tiny blank rather than allocating 300–700 px canvases.
2. **Completed match roots stayed reachable.** Cleanup previously waited for the next Play or reinjection. V1.71 schedules match teardown 650 ms after the authoritative terminal result, allowing the accepted 300 ms flashlight fade to finish. It restores BRIO hooks, draw gates, native HUD/cosmetic descriptors, resource maps, scene observers and array wrappers; cancels remaining match retries; detaches owned feature/inventory nodes; and drops scene queues, native/player/array references, decoded images and owned head/outline canvases. Report/session summaries remain available.
3. **A projection cache retained an entire scene.** The new WeakRef test initially failed. A local synthetic heap snapshot traced `Window → installation closure → v66View.root.r → player root → parent scene`. Normal map/set counters alone missed this path. V1.71 explicitly clears projection/pointer references at match completion. The final repeated-match test collects all completed scene roots.
4. **Idle overlay nodes.** Previously every encountered object could receive a durability overlay even when the option was disabled. V1.71 creates feature overlays only when their option is enabled; existing setting synchronization creates them when needed.
5. **Hidden ad browsing contexts and closed Locker resources.** Native ad-slot children and known ad-network iframes are removed instead of merely hidden and retained for restoration. A closed Locker drops its preview images, canvas backing storage and card DOM. It rebuilds from saved selections/live catalogue when opened. Three keyed slot records and one logo record replace the former growing installation/restore lists. Native child refreshes reuse the same owned panel; native host replacement disconnects and releases the previous observer, node and resize observation. Browser fixtures exercise 12 refreshes plus full host replacement. Native game canvases and unrelated content remain untouched. Already loaded third-party scripts and browser caches cannot be generally purged safely by this script.

## Verification and limits

`node tests/production-memory.cjs dist/brio-v71.min.js` uses actual Chromium and captured image assets with synthetic native-shaped matches; the engine source is parsed for bindings, **never executed**. It compares V1.70 with V1.71, checks 30 V1.71 match cycles, owned map/root cleanup and collectability of completed scenes, and records explicit-GC JavaScript heap samples. See `v71-memory-validation.json` for all samples and allocation geometry. The fixture enables all 18 General Advantages members and equips the original Kiln Current head/body/pickaxe/glider, with three remote players, 20 roof textures and 160 world objects per match. It does not substitute for real game/GPU measurement.

The final V1.71 fixture retained **zero completed scene roots** after 30 matches, versus one last scene in the V1.70 comparison. It created **zero large blank PNGs**, versus 24 in the baseline including startup blanks. Across matches 5–30, retained JS heap ranged from 5,283,872 to 5,461,820 bytes (177,948-byte spread). Initial-to-warm differences include code/UI/binding initialization, so they are not a per-match leak rate. Renderer RSS is recorded only when exposed by the executor process namespace; the final run returned `null` for both comparisons. No zero-memory, whole-browser or GPU measurement is claimed.

No claim is made that the user's entire 300→800 MB difference is eliminated or that the native browser/GPU immediately returns freed memory to the OS. The focused user pass records the same tab's memory footprint, and optional JS memory column, before installation and after each of at most two matches. No extra matches, forced GC, heap upload or diagnostic terminal are required. Continued growth remains actionable feedback rather than a reason to silently widen the test suite.
