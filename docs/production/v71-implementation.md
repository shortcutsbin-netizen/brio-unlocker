# V1.71 production candidate

Display v1.71, package 1.71.0, internal release/archive 71. Build via `npm run build:production-source` then `npm run build`. The deterministic generator is `tools/production/integrate-v71.cjs`, based on immutable V68 operational code plus current `src/production` modules. V70/prior archives, original captures/art/logs and historical documentation suffixes remain unchanged.

## Feedback changes

- Loot selection is a responsive grid of complete weapon cards, each with its own name/art and eligible Gold/Red options. Previously approved no-tier exclusions and Red-only weapons remain normalized in stored/effective targeting choices.
- General Advantages now has **18** included booleans. `allGlidersInvisible` remains an independent modifier and is deselected by the preset. The full-width description reflects its removal. Production descriptions live in `src/production/descriptions.json`; accepted historical design samples are unchanged.
- Used-modifier reporting collapses an intact preset only when all members, Large inventory and default warning thresholds match. Added options remain separate. Removing a member/default disqualifies collapse and expands individual used options; there is no Edited preset label. Reports still mean **used during the match**, so an option used earlier can remain listed after a mid-match change. A preset reduced before Play lists only what that match used. No continuous-challenge attestation is implied.
- Locker cards read native rarity from the live catalogue at render time. Original sets are Mythic/red; imported custom artwork is Common/gray. Rarity borders/glows retain a separate selected-state indicator.
- Preview now respects native back-to-front order: feet, hand group, body, head, glider. Pickaxe uses the native 24,10 resting anchor and 110×110 base; its artificial 1.12 root enlargement is removed, and body/head correctly occlude held items. The plain glider uses the native 250×250 dimensions rather than 200×200, with a 600×300 canvas to prevent clipping. Running body/head phase and native wrap masks remain shared/source-backed. In-match cosmetic resources/scales are unchanged. Exact animation timing and every native state cannot be guaranteed by the independent preview; no private game constructor/update is invoked and no new live probe is required.
- Socials now links to `https://github.com/shortcutsbin-netizen/brio_unlocked`. The new scrollable Changelog replaces the existing bottom-right `buildroyale-io_300x250_2` ad slot. Static, escaped, bounded release entries are in `src/production/changelog.json`; prepend future versions above 1.71. The first entry describes the complete released feature surface. Native home visibility/geometry is preserved. `src/production/home.js` owns exactly one record per slot and one logo record; ad-child refresh reuses the panel and full host replacement retires the old observer/node, preventing stale observers from removing new panels or accumulating across refreshes.
- The in-match Extras button and its creation/styles are removed. Native home Locker/Extras buttons remain. The former test-name prefix is no longer added; local capture uses authoritative decoded local ID or an exact native input name. No native keybind/input/protocol changes are added.
- Hell/trails, session layout and in-match cosmetics are accepted from user feedback. Victors is **deferred**, with no submission/list/auth code. No repeated Hell sweep is requested.

## Distribution preparation

`src/brio.js` is formatted and includes operational comments. `dist/brio-v71.min.js` remains the single-paste console payload. `dist/brio-v71.bookmarklet.txt` is an encoded one-click bookmark URL, prefixed **`javascript:` with one colon**; the user's `javascript::` spelling would introduce a syntax error. It decodes to `void ` plus the exact tested minified IIFE, preventing document replacement. Matching immutable v71 archives include all three artifacts. The browser test executes the bookmark URL, checks reinjection and verifies one installation/session reset.

Only the development repository is updated. The user will manually move readable source and the bookmarklet to the public distribution repository; the extensive visual README is deferred until development acceptance. Scripts still load native game assets and selected original/logo/icon art from existing pinned public development-art URLs. Copying the two files does not relocate those assets; preserve that host or deliberately change the distribution packaging later. Fonts/icon/art provenance documents remain in the development repository for the eventual README/notices.
